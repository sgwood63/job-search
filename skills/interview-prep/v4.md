## Context Loading — Session Reuse

This skill and its companion policies (`factuality`, `storage-routing`) are loaded once per session, not once per invocation. When prepping for several interviews (or several stages of the same interview loop) in one session, do not re-read this document or its companion policies on the second or later call — reuse what is already in context.

Re-read a document only when:
- It has not been loaded yet this session
- An auto-compaction event has occurred since it was last loaded
- The user asked to draft or promote a new version of this skill or a companion policy mid-session

**Compact guidance:** When prepping for several interviews back-to-back in one session, run `/compact` after every 5 preps if no manual compact has occurred recently — each prep pulls thought content, JD chunks, and profile context; unmanaged growth risks unpredictable auto-compaction that busts the cache prefix and forces a full reload of this document and its companion policies. (Pattern from `workflows/search-jobs/v3.md` Step 1 / Phase 3-PROCESS.)

## Required Reading Before Output

Loading method depends on `DATA_BACKEND` and whether `notes-index.md` exists for the application.

### OB1 mode — new model (`notes-index.md` present)

**Step 1a — Load notes-index.md:**

```
get_file('applications/<folder>/notes-index.md')
```

Parse the `## OB1 Thought Keys` section to extract thought IDs. Required keys to load:
- `domain_connection` (if present)
- `interview_prep_*` (all existing interview prep thoughts, if any)

**Step 1b — Fetch thoughts by ID:**

For each required thought ID found in notes-index.md:
```
fetch(<thought_id>)
```

Fetch in parallel: `domain_connection` thought + any existing `interview_prep` thoughts.

If `domain_connection` key is absent from notes-index.md (application created before v4 workflow), fall back to Step 1c.

**Step 1c — Retrieve job-description sections:**

```
search_chunks_semantic(
  query = "role requirements technical qualifications about the company",
  storage_key_prefix = "applications/<folder>/",
  limit = 3
)
```

This surfaces the Requirements and About sections of job-description.md without loading the full JD file.

**Step 1d — Profile quick-reference:**

Load `profiles/[matched-profile].md` in full via `get_file` (positioning strategy, target persona) — this file is short and always needed whole.

**What to log if a required thought is missing:**

If `domain_connection` is not in notes-index.md and `search_chunks_semantic` also misses the Domain Connection section: log "Domain connection not found — load partial context only" and proceed. Do not fabricate domain connection content.

### OB1 mode — legacy model (`notes-index.md` absent, `notes.md` present)

Fall back to v2 behavior:

**Step 1a — Retrieve interview-relevant sections from notes.md:**

```
search_chunks_semantic(
  query = "interview prep talking points questions cautions stage process domain connection",
  storage_key_prefix = "applications/<folder>/",
  limit = 6
)
```

**Required sections** — must appear in results or trigger fall-back (step 1b):
- Any chunk with `section_title` containing "Interview Prep" or the stage name
- `section_title` matching "Domain Connection" or a parent "Fit Assessment" chunk that contains domain connection text
- `section_title` matching "Process" (for stage inference)

**Step 1b — Fall-back for missing required sections:**

If any required section is absent from results:
- Call `get_file('applications/<folder>/notes.md')`
- Extract only the missing section(s) by heading — do not load the full file into context
- Log inline: "Semantic retrieval missed section '<title>' — loaded from full file."
- If all three required sections are missing, load the full file

**Step 1c and 1d:** Same as new model above.

---

### Local mode (`DATA_BACKEND=local`)

Full file reads — same as v1:
1. `applications/<folder>/notes.md` — full file, especially Interview Prep, Process, Fit Assessment sections
2. `applications/<folder>/job-description.md` — full file
3. `profiles/[matched-profile].md` — full file

**Why:** No vector DB in local mode — fall back to full file reads throughout. No degraded output, just no context savings.

## Output Structure (Required)

In order:

1. **Stage** — what interview type this is (from notes-index.md thought context or notes.md Process section; if unknown, state "stage not specified — assuming initial screen")
2. **Key talking points** — 3–5 role-specific points mapped to JD requirements, not generic SE talking points
3. **Questions to ask** — 3–5 questions tailored to this company and stage; avoid generic "what does success look like" unless nothing better applies
4. **What NOT to bring up** — from existing interview_prep thoughts or notes.md Differentiators/Caution sections if present; otherwise omit this heading rather than leaving it empty
5. **Signals to watch for** — what this company/stage is likely evaluating based on JD signals and company type

End with: "Interview prep loaded for [Company] — [Stage]. What aspect do you want to work through?"

## After Generating Prep (OB1 new model only)

After producing the prep brief, capture it as an OB1 thought and update notes-index.md:

```
capture_thought(
  content = "<full prep brief text>",
  metadata = {
    source_type: "job_search",
    thought_category: "interview_prep",
    application_id: <application_id>,
    application_folder: <folder>,
    company: <company>,
    profile_slug: <profile_slug>,
    stage_name: "<stage name>"
  }
)
→ save returned thought_id
```

Then update notes-index.md — append under `## OB1 Thought Keys`:
```
- interview_prep_<n> (<stage_name> <YYYY-MM-DD>): <thought_id>
```

where `<n>` is 1 + count of existing `interview_prep_*` keys.

Upload the updated notes-index.md via `upload_file`.

This ensures future interview prep sessions for the same application load prior prep notes from OB1 (Step 1b above) without needing to regenerate or load notes.md.

## Stage Inference Rule

If the user does not specify a stage, use the next upcoming stage from:
- New model: the `## Process` section in the `jd_analysis` thought, or from `job-description.md` chunks
- Legacy model: the Process section in notes.md

If the stage is unclear, default to "initial recruiter/hiring manager screen" and say so explicitly.

## No Fabrication (in addition to the factuality policy)

Do NOT invent:
- Company facts not found in retrieved thoughts or job-description.md
- Interviewer names or backgrounds not recorded in meeting_notes/interview_prep thoughts
- Specific questions the interviewer is "likely" to ask as though they are known facts

If a useful fact is missing, flag it as "worth researching before the call" rather than filling it in.

## Warm Connection Protocol

If existing `interview_prep` or `meeting_notes` thoughts, or `memory/APPLICANT-MEMORY.md`, lists a warm connection at this company, surface it in the prep brief — specifically who to mention, how the connection is relevant, and whether to reference it directly or let it serve as background context.
