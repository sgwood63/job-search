# Application Summary Skill

Generates (or regenerates) the full `notes.md` view for an application by fetching its OB1 thoughts and rendering them in canonical notes.md section order.

**This skill is OB1-only.** In local mode, `notes.md` is authored directly and this skill is not applicable.

## Inputs

| Name | Required | Description |
|---|---|---|
| `application_folder` | Yes | `YYYY-MM-DD-company-role` folder slug |
| `application_id` | No | OB1 UUID — if absent, derive from notes-index.md or `get_pipeline` lookup |

## Step 1 — Load notes-index.md

```
get_file('applications/<folder>/notes-index.md')
```

Parse:
- Header block fields: Status, Status Detail, Date, Profile, Source, Source URL, LinkedIn job ID (if present)
- `## OB1 Thought Keys` section: extract all thought IDs with their category labels

If notes-index.md is not found, stop and return error: "notes-index.md not found for this application — this skill requires the v4+ application model."

Derive `application_id` from notes-index.md `application_id` field if not passed as input. If not present in notes-index.md, call `get_application({folder_prefix: 'applications/<folder>/'})` to look it up.

## Step 2 — Fetch status from js_applications

```
get_application(<application_id>)
```

Use the returned `status` and `status_detail` fields as the authoritative values for the header block (overrides any stale values in notes-index.md).

## Step 3 — Fetch all thoughts

For each thought ID in notes-index.md `## OB1 Thought Keys`, fetch the thought content:

```
fetch(<thought_id>)
```

Fetch all in parallel. Collect results keyed by category. For missing thought IDs (key exists but thought fetch fails), note the gap and continue — do not error out.

**Expected thought categories and their notes.md sections:**

| thought_category | notes.md section |
|---|---|
| `jd_analysis` | ## JD Analysis |
| `fit_assessment` | ## Fit Assessment (including ### Domain Connection placeholder if domain_connection thought present) |
| `domain_connection` | ### Domain Connection (subsection of ## Fit Assessment) |
| `company_research` | ## Company Research |
| `resume_strategy` | ## Resume Strategy |
| `resume_evaluation` | ## Resume Evaluation Report (if present) |
| `interview_prep` | ## Interview Prep N — [Stage Name] (one section per thought, chronological order by thought created_at) |
| `meeting_notes` | ## Notes from Recruiter Interview (or ## Meeting Notes — [Date]) |
| `email` | Appended to ## Application Log as a note entry |
| `application_event` | ## Application Log entry |

## Step 4 — Render notes.md

Compose the full notes.md in the required section order below. For any thought category that has no thought (either no key in notes-index.md, or fetch returned nothing): omit the section entirely — no empty placeholders, no "pending" stubs.

**Required header block (always present):**
```markdown
# Notes — <Company> — <Role Title>

**Status:** <status from js_applications>
**Status Detail:** <status_detail from js_applications>
**Date:** <Date from notes-index.md>
**Profile:** <Profile from notes-index.md>
**Source:** <Source from notes-index.md>
**Source URL:** <Source URL from notes-index.md>
[**LinkedIn job ID:** <id>]  ← only if present
```

**Table of Contents** (always present, listing only sections that will be rendered):

```markdown
## Table of Contents

1. [JD Analysis](#jd-analysis)
2. [Fit Assessment](#fit-assessment)
3. [Resume Strategy](#resume-strategy)
...
```

**Section rendering rules:**

### ## JD Analysis
- Source: `jd_analysis` thought content verbatim
- Prepend: `**JD Source:** <source_url from notes-index.md>`
- Prepend: `**JD File:** jd-<company>-<role>.md`

### ## Fit Assessment
- Source: `fit_assessment` thought content verbatim
- Append as subsection if `domain_connection` thought exists:

```markdown
### Domain Connection

<domain_connection thought content verbatim>
```

### ## Resume Strategy
- Source: `resume_strategy` thought content verbatim

### ## Resume Evaluation Report
- Source: `resume_evaluation` thought content verbatim (if present)
- If absent: omit section

### ## Company Research
- Source: `company_research` thought content verbatim

### ## Notes from Recruiter Interview / ## Meeting Notes
- Source: `meeting_notes` thought(s), chronological order by `created_at`
- If multiple meeting_notes thoughts: render each as `## Meeting Notes — <date>`

### ## Process
- Source: from `jd_analysis` thought if it contains a "Hiring Process" or "Process" subsection; otherwise omit
- When present: extract the process steps from jd_analysis content

### ## Interview Prep N — [Stage Name]
- Source: each `interview_prep` thought, rendered in chronological order (`created_at`)
- Section title: `## Interview Prep <n> — <stage_name from thought metadata>`
- Content: thought content verbatim

### ## Process Reminder
- Render as: `_See ## Process above for hiring stages. Next step: see Application Log._`
- Omit if no Process section

### ## Application Log
- Source: all `application_event` thoughts + any `email` thoughts, chronological order
- Format each as: `- [date from thought created_at] — <thought content (first line only if multiline)>`
- Always include at minimum the creation entry: `- [<Date from header>] — Application created via <Source>`
- For `email` thoughts: `- [date] — Email: <thought content (first line)>`

## Step 5 — Upload notes.md

```
upload_file('applications/<folder>/notes.md', <composed content>, 'text/markdown')
```

## Step 6 — Verify Status Sync

After upload, confirm that `**Status:**` in the uploaded notes.md matches the value returned by `get_application` in Step 2.

If they differ: log "Status mismatch detected — notes.md status updated to match js_applications." Do not error.

## On-Demand Use

This skill can be called explicitly by the user (e.g., "regenerate notes for Acme Corp") or by other workflows:

- **`create-application/v4`**: calls after all 5 initial thoughts are captured (Step 4e)
- **`interview-prep/v3`**: may call if notes.md is stale or missing (optional — interview prep loads thoughts directly and does not require notes.md)
- **User request**: "show me the full notes for [application]", "regenerate notes.md for [company]"

## Error Handling

| Condition | Action |
|---|---|
| notes-index.md not found | Stop with error: skill requires v4+ application model |
| All thought fetches return nothing | Stop with warning: "No thoughts found for this application — notes.md cannot be generated. Check that process-jd v2 or later was used to create this application." |
| Partial thought fetch failures | Continue with available thoughts; log each missing category inline in the output |
| upload_file fails | Retry once; if still failing, output composed notes.md as text so user can copy manually |
